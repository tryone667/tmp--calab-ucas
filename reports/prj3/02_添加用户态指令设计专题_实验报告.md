## 二、设计思路

### 2.1 乘法：放进 ALU（单周期）

乘法按"ALU 的一个普通运算"实现：`alu_op` 扩展出 15/16/17，`alu.v` 内计算两条 64 位积——无符号 `prod_u` 与有符号 `prod_s`；`mul.w` 取低 32 位，`mulh.w` 取有符号高 32 位，`mulh.wu` 取无符号高 32 位。综合映射到 DSP，无需额外周期。

### 2.2 除法：独立 `divider` 模块（多周期）

`div.w / mod.w / div.wu / mod.wu` 由一个独立模块 `divider` 完成（接口 `clk / reset / start / unsign / mod / a / b / busy / result`），在 `mycpu_top` 中显式实例化：

- 商向零截断、余数取被除数符号（有符号版本）；
- `busy` 期间冻结前段（消费者在 ID 停等），结果经 EX→MEM→ID 前递，保证不把未完成值送出去；
- **优化（2026-10-14）**：① 平凡快速路径——除数/被除数 0、`|被除数| < |除数|` 时 accept 当拍出结果；② 对齐迭代——除数左移对齐被除数最高位，只产生有效商位，平均迭代数从固定 32 拍降到个位数（上界仍为 32 拍）。

### 2.3 exp11 的两处扩展

- **分支**：ID 判出（signed / unsigned 两套比较器），命中当拍冲刷 IF / if_req 并改道，只付 2 个气泡。
- **字节/半字访存**：`ls_type` 随流水线传递（0 none / 1-3 st.b/h/w / 4-6 ld.b/h/w / 7-8 ld.bu/hu）；写通路按地址生成字节掩码与重复数据，读通路按地址选字节/半字并做符号/零扩展。

## 三、重点、难点与取舍

1. **多周期除法 vs 吞吐**：选择"EX 内多周期 + 停顿"换取面积与实现简单；再用"对齐迭代 + 平凡快路径"把停顿拍数压下来（效果见第四节）。
2. **除法结果的消费冒险**：商在 EX 完成后才可用，消费者在 ID 停等到它能从 MEM 前递过来，避免错误前递。
3. **结构整洁（验收反馈整改）**：除法器独立成模块并显式例化；`alu_op` 由 22 位收窄到 18 位（删掉 ALU 内根本用不到的 div/mod 四位）；div 判定只保留单一定义（`id_alu_is_div` → 流水线寄存器 `ex_alu_is_div`），去除语义重复的旧写法；全量"定义了但未使用"信号审计清零。
